# Inventory and material-shortfall analysis

1. Discover only the required material × location × time × scenario module/line item and its units, sign and axes. Known candidate: `IEO200 - Inventory EO by DC` / `Shortfall (U)`, but verify before use. Scenario 1 is the default unless user says otherwise. For a relative 26-week request, resolve the current model week and 26 actual consecutive model week members with the shared anchor workflow. Do not interpret FY25 as wall-clock current year.
2. To test below-zero inventory or safety-stock breaches, find actual ending forecast inventory and safety-stock measures. If only `Shortfall (U)` exists, report **unmet-demand triage** explicitly; if the user requires inventory and it cannot be read, say it cannot be established. Do not assume a blank equals zero or a shortfall is negative; verify sign convention. Never sum weekly carried-forward shortages into a purchase requirement.
3. Read one bounded paged material × time view for a selected site and Scenario 1 when performant, `limit` ~500, continue to `has_more=false`. If it fails once, slice a week at a time with leaf materials, paging each. Across all sites, split by location/week; don't scan the full cross product in one query. Record which site–weeks are covered. Avoid `sql_schema` and `sql_query` when `read_cells` can do the read directly.
4. Report every material/location/period with observed inventory < 0 or < safety stock, or all observed unmet-demand weeks if using that different measure. For a vague 'significant' request, show largest observed exceptions without inventing a threshold. State coverage, first/worst week, scenario, horizon and read date; if partial, don't claim an exhaustive set. Pass material identifiers and first risk weeks to a downstream workflow without rerunning the same forecast read.
